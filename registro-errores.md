# Registro de Errores (Bug Log)

Documento vivo para registrar bugs encontrados durante las pruebas manuales o automatizadas, en cualquiera de los chats del proyecto ("Crear la app", "Diseño QA", "Automatización"). No reemplaza un issue tracker real (Jira, GitHub Issues) — es la versión liviana para este proyecto de capacitación.

**Severidad vs. Prioridad (para no confundirlas):**
- **Severidad** = qué tan grave es el impacto técnico/funcional (¿rompe el flujo? ¿hay workaround?), es objetiva.
- **Prioridad** = qué tan urgente es arreglarlo para el negocio/roadmap, puede ser subjetiva y cambiar con el contexto (ej. un bug de baja severidad pero que bloquea una demo puede tener prioridad alta).

## Convenciones

- **ID:** `BUG-XXX` correlativo. Como este documento lo puede editar cualquier chat del Proyecto, releelo primero para tomar el próximo número libre de una versión fresca — no asumas que el último ID que viste sigue siendo el más alto, otro chat puede haber cargado un bug mientras tanto.
- **Severidad:** Crítica (bloquea el uso de la app) / Alta (rompe un flujo principal, sin workaround) / Media (rompe un flujo secundario o hay workaround) / Baja (cosmético, no afecta funcionalidad).
- **Estado:** Nuevo → En análisis → En progreso → Resuelto → Verificado → Reabierto (si vuelve a fallar) / No es bug (si se descarta).
